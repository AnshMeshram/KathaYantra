# KathaYantra — Local AI Archivist Service Specification
### *Preserve the story. Trace the source. Respect the culture. Keep the AI honest.*

---

## 1. Executive Overview

The **KathaYantra Local AI Archivist** is an offline-capable, retrieval-augmented intelligence service designed to assist researchers, folklorists, and curious readers in exploring 300 verified folklore narratives and modern urban legends across 15 countries.

Unlike cloud-dependent LLM chatbots that hallucinate citations and blur cultural traditions, the KathaYantra Archivist adheres to strict architectural constraints:
1. **Grounded Evidence Retrieval:** The AI relies strictly on retrieved, publication-eligible story records from the local SQLite FTS5 index.
2. **Deterministic Source Attributions:** Bibliographic citations and URLs are attached directly by the backend from verified record metadata. The language model is never trusted to generate URLs or bibliographic citations.
3. **No Synthetic Folklore in Authentic Archive:** Fictional narratives generated by the creative engine are strictly segregated to `GeneratedFictionRecord` models, tagged with mandatory disclaimers, and quarantined in `data/processed/generated_fiction/`.
4. **Honest Insufficient Evidence Handling:** When retrieval finds zero matching records, the system responds with an explicit `insufficient_evidence` classification rather than inventing plausible-sounding lore.
5. **Local-First Privacy:** Runs entirely on the host machine using **Ollama** and open-weight **Gemma 2**, transmitting zero queries to third-party cloud APIs.

## 2. System Architecture & Information Flow

```
[ User Inquiry ]
       │
       ▼
[ Query Normalizer & Stopword Filter ] ── Strips conversational noise
       │
       ▼
[ SQLite FTS5 Lexical Search Index ] ── BM25 ranking across title, summary, motifs, cultural context
       │
       ├── No matches found ───────────> [ Return AIAnswerType.INSUFFICIENT_EVIDENCE ]
       │
       ▼ (1 to 5 Eligible Records)
[ Context Assembly & Prompt Injector ] ── Delimited [RETRIEVED ARCHIVE RECORDS] + System Invariants
       │
       ▼
[ Local Ollama Runner (Gemma 2) ] ──── Inference via POST http://127.0.0.1:11434/api/chat
       │
       ├── Connection Error / Offline ─> [ Return AIAnswerType.MODEL_UNAVAILABLE + Deterministic Records ]
       │
       ▼
[ Answer Validator & Citation Attacher] ── Attaches verified AISourceCitation payloads from metadata
       │
       ▼
[ Structured AIQuestionResponse ] ───── Returned to client
```

## 4. Prompt Engineering & Injection Defenses

Prompt templates are version-controlled in [`app/prompts/`](file:///C:/Users/shrin/Desktop/Hactoberfest2026/KathaYantra/app/prompts/):
- `archivist_system_v1.txt`: Factual archival assistant prompt.
- `story_comparison_system_v1.txt`: Neutral comparative analysis prompt.
- `story_generation_system_v1.txt`: Creative narrative generation prompt.

### Security Defenses:
1. **Role Delimitation:** Retrieved records are encased in explicit `[RETRIEVED ARCHIVE RECORDS]` and `[END OF RETRIEVED ARCHIVE RECORDS]` boundary blocks.
2. **Instruction Neutralization:** The archivist prompt explicitly commands the model to treat any directives inside retrieved records as historical story dialogue, never as system instructions.
3. **Input Sanitization:** User questions are bounded to `AI_MAX_INPUT_CHARS` (1000 characters) and stripped of illegal control characters.
4. **Citation Isolation:** Citations returned in the JSON payload are extracted strictly from trusted metadata by backend code, rendering model-hallucinated URLs completely inert.
